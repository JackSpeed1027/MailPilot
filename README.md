# MailPilot v0.5：邮件阅读、手动回复与智能起草

> **v0.5 阅读体验更新（2026-10-13）**：邮件列表更便于扫读，阅读页可跳转摘要/译文/原文，搜索后返回保留筛选，设置分组展开，窄屏采用底部导航。升级后关闭旧运行窗口并重新双击 `Start-MailPilot.cmd`。具体操作和安卓技术路线见 [v0.5 界面验收与安卓路线](docs/v0.5-界面验收与安卓路线.md)。当前是 Windows 本机网页工作台，尚未交付 APK。




MailPilot 在你的 Windows 电脑上读取 QQ、163、Gmail 的新邮件，用模型生成中文摘要，再通过 WxPusher 发到你的手机。通知会显示**谁发来的、邮件上的收件地址、实际在哪个邮箱收到**。

本文按第一次使用的顺序写。建议先接通一个 QQ 邮箱，成功后再加入其他邮箱。所有项目文件都在 `D:\Work\Code\Python\MailPilot`。

**已有配置的用户**：先在旧运行窗口按 Ctrl+C 停止，再双击项目里的 `Start-MailPilot.cmd`。浏览器会自动打开设置页，原邮箱和历史邮件保留。授权码、API Key 和 AppToken 直接在页面填写，保存后自动启动收件，不再逐项在控制台输入。

外文新邮件现在分开提供中文摘要、全文中文翻译和清洗后的原文；长邮件分段翻译，失败、超限或截断会明确提示。手机短邮件可看原文和译文，长邮件通知明确标为节选；全部内容在本机详情查看。附件目前只显示名称。

产品架构见 [系统架构与产品规划](docs/系统架构与产品规划.md)。每版问题、技术决策与性能证据见 [版本演进与技术复盘](docs/版本演进与技术复盘.md)。本版测试步骤见 [v0.3 用户验收](docs/v0.3-用户验收.md)。

**v0.4 新功能**：修复正文、主题和旧记录中的 `&nbsp;` 等编码显示；详情标明摘要来自模型还是本机提示。对应邮箱开启 SMTP 后，可在详情写回复、保存草稿、预览全文，再手动确认发送。设置里可配置回复偏好，“按我的偏好智能起草”使用两个只读工具生成可修改草稿，不会自动发信。操作步骤见 [v0.4 用户验收](docs/v0.4-用户验收.md)。

**数据库仍是本机 SQLite**：`data/mailpilot.sqlite3`。不需安装数据库、不需租服务器。未来登录与跨设备同步再引入独立后端和 MySQL；当前不增加运行成本。

## 1. 先分清需要准备的东西

| 名称                | 是什么             | 从哪里取得                    | 什么时候输入  |
| ----------------- | --------------- | ------------------------ | ------- |
| 邮箱地址              | 你自己的完整邮箱地址      | 如你实际使用的 `123456@qq.com`  | 设置页面    |
| 显示名称              | 你给邮箱起的备注，方便区分来源 | 自己起，例如 `QQ主邮箱`、`工作163`   | 设置页面    |
| 邮箱授权码             | 允许程序读取邮箱的专用凭据   | QQ/163 邮箱设置中生成           | 页面密码框 |
| Gmail 应用专用密码      | Gmail 的第三方程序凭据  | Google 账号安全设置中生成         | 页面密码框 |
| WxPusher UID      | 接收通知的那个人的编号     | WxPusher 用户列表或官方 UID 演示页 | 设置页面    |
| WxPusher appToken | 你的推送应用调用接口的凭据   | WxPusher 管理后台            | 页面密码框 |
| 模型 API Key        | 让程序调用摘要模型的凭据    | 模型服务商的 API 平台            | 页面密码框 |

**显示名称不用注册，也不是登录账号或密码。** 比如邮箱地址填你自己的 QQ 邮箱，显示名称填 `QQ主邮箱`，以后通知就能标出“实际收件账号：QQ主邮箱 <你的邮箱地址>”。这个备注不会更改 QQ 邮箱本身的昵称。

邮箱授权码、应用专用密码、API Key、appToken 都是私密凭据，不要发到聊天里。下面的示例邮箱和 `UID_……` 是说明格式用的，不能原样使用。

本版使用官方的**标准推送：appToken + UID**。官网还提供 SPT 极简推送，但 MailPilot 当前没有接入它，因此不要把 SPT 填到 appToken 的位置。[标准推送接口说明](https://wxpusher.zjiecode.com/docs/api-reference.html)

### 2.2 创建一个属于你的推送应用

1. 在电脑浏览器打开上面的管理后台，按页面提示用微信扫码登录。
2. 找到应用管理中的“创建应用”入口。页面按钮名称可能随版本变化，以后台实际显示为准。
3. 应用名称可以填 `MailPilot`，说明可以填 `个人邮件摘要通知`。这里的“应用”只是后台的一个推送项目，不要求你开发手机 App。
4. 本版不需要回调服务器；回调地址等可选字段先留空。如页面出现新的必填项，按官网说明填写，不要编造网址。
5. 创建后打开这个应用的详情或 appToken 管理页面，复制它的 **appToken**，留待在设置页面输入。不要点“重置”来查看：重置会让旧 token 失效。

### 2.3 用自己的手机订阅这个应用

1. 在刚创建的 **MailPilot 应用**里找到关注/订阅二维码或链接。
2. 用接收通知的本人账号扫码，按页面提示完成订阅。
3. 回到后台的用户管理/微信用户管理，确认这个应用的用户列表中出现了你，复制对应的 **UID**。[用户管理入口](https://wxpusher.zjiecode.com/admin/main/wxuser/list)
4. UID 的完整内容以 `UID_` 开头。后面还有一串字符，需要全部复制。

如果找不到 UID，可以打开[官方演示页](https://wxpusher.zjiecode.com/demo)，用本人微信扫描页面二维码，查看页面显示的 UID。**获取 UID 后仍要订阅你自己的 MailPilot 应用**；只扫演示页、只登录后台，都不能替代这一步。

### 2.4 在手机上开启接收通知

从[官方下载页](https://wxpusher.zjiecode.com/download/)选择你的手机系统，安装客户端，按当前客户端的登录/绑定提示接入本人身份，并允许系统通知。确认接收身份与后台订阅用户一致，最后用本文第 6 节的测试通知验证。

如果你希望消息出现在**微信内**，请按官方当前的微信接收通道说明完成绑定和激活。现在官网也提供独立手机客户端，不能理解成“扫码登录后台后，微信就一定能持续收到消息”；微信通道的激活与额度规则以[官方说明](https://wxpusher.zjiecode.com/docs/)为准。

### 2.5 两个值不要填反

| 你拿到的内容 | 用途 | 在 MailPilot 中填哪里 |
| --- | --- | --- |
| `UID_` 开头的完整 UID | 指定你这个接收人 | `WxPusher 本人 UID` |
| 你的应用 appToken，通常以 `AT_` 开头 | 授权 MailPilot 发送通知 | `MAILPILOT_WXPUSHER_TOKEN（输入隐藏）` |

微信号、昵称、AppID、二维码图片、SPT 都不能替代这两个值。UID 和 appToken 必须属于可以给本人发送消息的同一个应用订阅关系。

## 3. 准备邮箱授权码

IMAP 可以理解为“允许 MailPilot 读取收件箱”的服务。服务器地址程序已经按邮箱类型设置好了，向导不用你填写端口。

### QQ 邮箱

vzakarutvebwjffe

1. 在电脑打开 [QQ 邮箱网页版](https://mail.qq.com/)，登录你的邮箱。
2. 进入“设置”，寻找“账号”或账号安全/第三方客户端相关设置。
3. 找到 `POP3/IMAP/SMTP` 服务，开启 **IMAP/SMTP 服务**。
4. 按页面要求完成手机等安全验证，生成并复制**授权码**。如果已开启服务，可在授权码管理中为 MailPilot 生成新的授权码。
5. 在设置页面，把授权码粘贴到该 QQ 邮箱对应的“邮箱授权码”密码框中。

授权码不是 QQ 登录密码，也不是手机收到的一次性短信验证码。不同网页版的菜单位置可能不同，可参照[华为官方的 QQ 邮箱授权码图文说明](https://consumer.huawei.com/cn/support/content/zh-cn16108643/)，最终以 QQ 邮箱当前页面为准。

### 163 邮箱

1. 在电脑打开 [163 邮箱网页版](https://mail.163.com/)，登录你的邮箱。
2. 进入“设置”，寻找 `POP3/SMTP/IMAP`。
3. 开启 **IMAP/SMTP 服务**，按提示完成手机验证。
4. 在开启服务流程或“客户端授权密码/授权码”管理中生成授权码并复制。
5. 在页面输入这个授权码，不要输入网易账号的登录密码。

菜单随版本可能变化；找不到时进入网页版帮助中心，搜索“IMAP”或“客户端授权码”。服务和授权码的设置示例也见[华为云官方用户指南](https://support.huaweicloud.com/usermanual-roma/romaconnect-usermanual-pdf.pdf)中的“配置 163 邮箱授权码”。

### Gmail

1. 确认这台电脑的网络能够连接 Google/Gmail 服务。
2. 打开 [Google 账号安全设置](https://myaccount.google.com/security)，开启两步验证。
3. 打开 [应用专用密码页面](https://myaccount.google.com/apppasswords)，按提示验证身份。
4. 应用名称可填 `MailPilot`，生成应用专用密码。复制这组 16 位字符；粘贴到程序时去掉展示时用于分组的空格。
5. 邮箱地址填完整 Gmail 地址，页面的授权码框填应用专用密码，不填 Google 登录密码。

部分工作/学校账号、启用高级保护或特定两步验证设置的账号不提供应用专用密码；管理员也可能禁止 IMAP。本版尚未实现 Google OAuth 登录，遇到这些限制先接入 QQ/163，不要关闭两步验证来尝试。详见[Google 官方应用专用密码说明](https://support.google.com/accounts/answer/185833?hl=zh-Hans)。

### 5.3 页面每一项怎么填

| 页面字段 | 填写说明 |
| --- | --- |
| 邮箱服务商 | QQ、163、Gmail 中选一个；程序自动选择 IMAP 服务器和 TLS 993 端口 |
| 邮箱地址 | 自己的完整邮箱地址，例如你实际使用的 `name@qq.com` |
| 显示名称 | 自己起的备注，例如“工作邮箱”，不是用户名或密码；新邮箱留空使用地址 |
| 邮箱授权码 / 应用专用密码 | 第 3 节在邮箱设置中生成的值，不是普通登录密码 |
| 云摘要与翻译授权 | 想让模型阅读这个邮箱的普通邮件，就勾选；附件不包含在授权里 |
| API 基础地址 | 第 4 节的 HTTPS 地址，例如 `https://api.deepseek.com/v1`，不要加 `/chat/completions` |
| 模型名称 | 服务商支持的名称，例如 `deepseek-flash`；已有可用名称可保留 |
| API Key | 在模型服务商后台获取的私密 Key，不是模型名称 |
| 摘要详细程度 | 简短、均衡、详细；中文摘要与全文译文分别显示 |
| 外文全文翻译 | 推荐开启；同一封邮件可能额外产生一次或多次模型调用 |
| 全文翻译上限 | 默认 30000 字符；超过时提示，范围 1000～100000 |
| 每日调用尝试上限 | 摘要、分段翻译共享，默认 100，不是人民币预算 |
| WxPusher UID | 订阅应用后自己的 `UID_` 开头编号；第 2 节有完整获取步骤 |
| WxPusher AppToken | 自己创建的推送应用凭据，和 UID 分别填写 |
| 收件间隔 | 默认 60 秒，范围 15～3600 |

第一次先添加一个邮箱。点击 **保存并应用配置** 后，等待设置页/首页显示收件已启动，再刷新首页查看各邮箱连接状态。然后回设置页添加第二个邮箱，每次添加一个；不需要重新填写已有邮箱的密钥，留空保留。

尚未准备好模型或 WxPusher 时，可以先关闭对应开关，添加邮箱进行收件验证。没有勾选云处理的邮箱不会将正文发送给模型。

### 5.4 密钥不回显，怎样保存

密码框中的值提交后会清空，页面只显示“已配置”或“尚未配置”，不显示原密钥。普通设置保存在 `config.json`；授权码、Key、AppToken 不写入该文件。

- 默认**仅本次运行使用**：关闭程序后重启，需要在页面重新填写。
- 勾选**将本次新输入的密钥保存到 Windows 凭据管理器**：同一项目、同一 Windows 用户下次启动可自动读取。属于本机凭据保存，不是保存到云端。
- 密钥留空：保留已有值，不是清除。要把已记住的密钥改成仅本次，重新输入并取消勾选。
- Windows“凭据管理器 → Windows 凭据”里可删除 `MailPilot/` 开头的项目。不要误删其他应用的凭据。
- 更换 API 地址时必须重新填写 Key。程序按服务地址隔离密钥，避免把旧 Key 发给另一个服务商。

首次保存若缺少启用功能需要的密钥，配置仍保存，但不会开始收件，页面会提示补充。保存后等待正在进行的请求结束再切换配置；已发出的请求无法撤回。旧邮件和通知不会自动重算、重发。

### 5.5 修改已有配置

已有邮箱备注、云处理授权、授权码、模型地址/名称/Key、推送 UID/AppToken、摘要风格、翻译设置、收件间隔都可以在页面修改。添加邮箱也在同一页面完成。

回复功能的 SMTP 开关与智能回复偏好也在同一页面配置。邮箱地址暂不在原账号上直接修改，避免串用旧的收件进度；可添加新地址。删除账号、自定义 IMAP 文件夹/服务器、数据目录、邮件大小上限仍是进阶 JSON 设置，需先停止程序，谨慎编辑，不能删除 `data` 重新配置。

命令行 `setup`、`run --prompt-secrets` 仍保留给进阶用户；`web` 是只读浏览，`run` 下的旧偏好页保存会停止进程。日常请使用 `ui` 或启动脚本获得自动应用配置的页面。

```powershell
python -m mailpilot test-push --prompt-secrets
```

此命令只询问 WxPusher appToken，会真的发一条“MailPilot 测试通知”。看到 `accepted` 表示服务商已接受发送任务；**还要到手机确认看到了消息**，才能判断接收链路通了。

### 6.2 测试摘要模型

```powershell
python -m mailpilot test-model --prompt-secrets
```

此命令只询问模型 API Key，会把一封合成的会议邮件发给模型，可能产生少量 API 费用，不会发送你的真实邮箱正文。返回结果中的 `mode` 为 `model` 且有中文摘要，表示这次模型测试通过；`fallback` 是降级结果，需要检查接口、模型、密钥及额度。如果没有启用模型，可以跳过本步骤。

### 6.3 测试邮箱登录

```powershell
python -m mailpilot doctor --online --prompt-secrets
```

按提示输入凭据，确认每个邮箱显示“TLS IMAP 登录成功”。这个检查不会移动收件进度，不会给历史邮件建立采集基线；模型和推送仍要通过前面两项分别验证。

### 6.4 正式启动并发送一封新测试邮件

再次运行第 5.2 节的启动脚本，或在 Python 已可用的情况下执行：

```powershell
python -m mailpilot ui
```

1. 在页面保存配置，等待收件状态显示已启动，浏览器打开[本机控制台](http://127.0.0.1:8788)。检查对应邮箱连接正常。
2. **首次成功连接只记录起点，跳过已有邮件。** 请等对应邮箱成功连接后，再从另一个邮箱给它发新邮件。
3. 测试主题用“MailPilot会议测试”，正文用“请确认周五上午10点的会议，预算12800元。”，不要用验证码邮件测试普通摘要。
4. 默认约每 60 秒检查一次，加上模型和通道耗时，等待一两分钟再看控制台和手机。
5. 确认通知中的发件人、实际收件账号正确，普通邮件有中文摘要。

**收件地址与实际收件账号可能不同，这是正常的。** `To` / `Cc` 来自邮件头；“实际收件账号”是 MailPilot 从哪个邮箱读到了邮件。转发、别名和密送时，两者不一定一样，也不能从邮件头推断所有密送对象。

电脑和运行窗口需要保持开启，电脑睡眠、断网或退出程序后不会继续检查。按 `Ctrl+C` 停止。控制台只供这台电脑查看，手机打不开 `127.0.0.1`；手机通过 WxPusher 接收通知。

## 7. 常见问题

| 现象 | 怎么处理 |
| --- | --- |
| 不知道“显示名称”填什么 | 填 `QQ主邮箱` / `工作163` / `海外Gmail`，自己看得懂就行 |
| 输入凭据时没有文字或星号 | 正常的隐藏输入；粘贴一次按回车 |
| 显示“配置已存在” | 不要反复运行 setup；按第 5.5 节编辑 `config.json`，保存后重启 |
| “未添加邮箱” | 在第一个“邮箱类型”提示里输入 `qq` 等，不能马上回车 |
| “找不到 Python”或“不是命令” | 优先用启动脚本；已有虚拟环境时使用 `.\.venv\Scripts\python.exe`；仍失败需安装/修复 Python 3.11+ 并重新打开终端 |
| QQ/163 登录失败 | 确认完整地址正确、IMAP 开启、输入的是该邮箱授权码；新生成授权码后用新值重启 |
| Gmail 登录失败/超时 | 确认 Google 网络可达、使用应用专用密码且无分组空格、账号政策允许 IMAP；本版不支持 OAuth |
| “缺少凭据” | 日常在设置页面填写密码框；进阶诊断命令才使用 `--prompt-secrets`，不要把密钥拼进命令 |
| 模型显示“未允许云摘要” | 对应邮箱的 `allow_cloud` 需要为 `true`，`llm.enabled` 也要为 `true`；修改后重启 |
| “自动摘要暂不可用” | 先运行 test-model，检查 API 地址、可用模型、API Key 和平台额度；当前向导里的旧默认模型需要按第 4 节确认 |
| 模型测试成功但某封邮件没有摘要 | 验证/登录类邮件会被保护；无正文、超出大小限制、调用次数用尽也会降级提示 |
| 手机没收到测试通知 | 检查 appToken 和 UID 有没有填反、本人是否订阅此应用、接收通道是否绑定/激活、手机通知权限是否开启 |
| `accepted` 但手机没有显示 | 它只代表发送任务被接受；继续检查 WxPusher 的发送记录和接收客户端，不能据此认定手机已收到 |
| 启动后没收到旧邮件通知 | 首次连接会跳过历史邮件；成功连接后重新发送一封测试邮件 |
| 控制台打不开 | 确认程序还在运行，地址是 `http://127.0.0.1:8788`，并且在运行它的电脑上打开 |
| 端口 8788 被占用 | 先关闭旧 MailPilot/演示服务；也可用 `python -m mailpilot run --port 8789 --prompt-secrets` 并打开 8789 |

遇到不能解决的问题，可以把**报错文字、执行了哪一步、邮箱服务商类型**告诉我。不要提供授权码、API Key、appToken，也不要贴真实敏感邮件正文。

## 9. 当前版本的行为和边界

- 仅收件、摘要和推送，不发邮件、不删除/移动邮件，也不修改邮件已读状态；默认读取收件箱。
- 普通邮件只有对应邮箱允许云摘要时，才会将清洗后的主题/正文发给你选的模型服务商；摘要及必要的邮件信息会经 WxPusher 传递。
- 验证/登录类邮件采用规则保护，隐藏主题和正文，仅提醒去原邮箱查看；规则无法保证识别所有敏感内容。
- 普通邮件的清洗正文、摘要、回复草稿、发信状态与 Agent 步骤保存在本地 SQLite；原始邮件报文不落盘。小邮件会在内存读取完整 MIME，包括附件编码字节，但不单独保存或分析附件。默认超过 2MB 时只读取邮件头并提示。
- 短中文邮件通常一次摘要调用；外文邮件额外按约 2000 字符一段全文翻译，长邮件再合并各段事实生成摘要。每日模型尝试上限默认 100，摘要、翻译和智能起草共享。主摘要最初读取前 12000 字符，长外文只有全文翻译及合并均成功才标为全篇摘要；未覆盖完整会提示。
- 同一个账号的精确重复报文抑制重复通知；同一邮件到达不同邮箱会分别保留来源并通知。
- 模型不可用时保留邮件并提示去邮箱查看；推送结果不确定时不自动重发，避免重复通知。
- 尚未实现开机自启动；支持 Windows 凭据管理器，保存过的密钥下次启动可自动读取。

## 10. 进阶命令与项目文件

不需要在首次配置时执行本节。

查看状态（无需输入密钥）：

```powershell
python -m mailpilot status
```

推送明确失败时，程序有限次退避重试；超时或发送中崩溃可能标记为 `unknown`，表示无法确认服务商是否已经收到。先检查手机和发送记录，停止运行进程，再按控制台显示的真实任务编号重新入队。下面的 `3` 只是示例：

```powershell
python -m mailpilot retry 3
```

`unknown` 任务只有在接受重复通知风险后才使用：

```powershell
python -m mailpilot retry 3 --accept-duplicate-risk
```

重新入队不会立即发送，需要下次启动 `run`。已 accepted 的任务不会由此重发。

如果提示邮箱 UIDVALIDITY 变化，该账号会暂停，需要检查后重新建立基线。**这个操作会跳过该账号当前所有已有邮件**，不可用来补收历史邮件。停止程序后，填写 `config.json` 中真实的 `id`；向导第一个 QQ 邮箱通常为 `qq1`，模板里则可能为 `qq`：

```powershell
python -m mailpilot baseline --account qq1 --prompt-secrets
```

离线开发测试：

```powershell
python -B -m unittest discover -s tests -v
```

| 文件/目录 | 内容 |
| --- | --- |

## 11. 在应用里回复与智能起草

重启后在设置里对应邮箱勾选“允许在本机手动发送回复（SMTP）”，并确认邮箱官网 SMTP 已开启。旧配置默认关闭，不会自动发送。详情 → 写回复 / 智能起草 → 手写正文 → 保存草稿并预览 → 核对发件邮箱、收件人、全文 → 确认发送。

发件人是实际收件账号，回复目标优先 Reply-To，否则 From，单人回复不附带 Cc 或附件。默认官方 SMTP + TLS 465。旧记录缺少 Reply-To 会提醒；无效、多地址或敏感邮件需到原邮箱处理。

设置页的“智能回复偏好”提供专业/亲切、简短/均衡/详细、跟随原邮件/中文/英文、惯用署名及偏好说明。模型与该邮箱云处理授权开启后，普通完整正文最多12000字符的邮件可以点击“按我的偏好智能起草”。最多3轮请求，共享每日上限；模型选择两个只读工具，草稿只能由用户确认发送。署名由本机添加，不上传给模型。没有自动学习历史习惯，语义正确性需用户核对。

发送失败或不确定会保存状态；提交期间超时、程序崩溃可能已送达，不能自动重发。服务器接受不等于对方已读。本版不保证原邮箱“已发送”文件夹同步，只提供本机记录。

## 12. 数据库与后续 MySQL

SQLite 数据库文件位于配置中 `data_dir` 指定目录，默认是项目 `data/mailpilot.sqlite3`。现有个人邮件和草稿不在云端。使用 WAL 与短事务，界面只通过 Store 访问数据。

若未来做多设备同步：客户端保留 SQLite，统一后端在服务器上运行，MySQL 与后端部署在同一台或私有网络内；客户端通过 HTTPS 调后端，不直接连 MySQL。开发可在自己的电脑装 MySQL；正式共享服务可租服务器，也可使用持续在线的自有设备，但需要处理网络、备份与运维。单机应用不要求每个用户安装 MySQL。

换 MySQL 不是改连接地址即可；SQLite 的占位符、JSON 查询、索引、事务、迁移和驱动需要适配。取得实际同步/并发需求后再做数据访问接口与迁移，不提前加数据库服务或 Redis。

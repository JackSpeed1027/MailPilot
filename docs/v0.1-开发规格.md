# MailPilot v0.1 开发规格

本版根据用户最新要求确定：核心为邮件总结、指定渠道推送、发件人和收件账号标识。第一版部署 Windows，接入 QQ、163、Gmail，渠道为 WxPusher。本规格取代旧路线图中“验证码优先”的版本范围。

交付内容：多账号只读增量采集；每封普通邮件的中文摘要、要点、待办提示；来源展示；持久化发送队列；有限重试和结果不确定保护；本机只读控制台；交互配置与隐藏输入凭据；离线演示和回归测试。

技术决策：

- Python 标准库 + SQLite。优先零依赖运行，后续有控制台配置编辑和用户管理需求时再考虑 FastAPI。
- 摘要使用一次结构化模型调用，用户可配置兼容 API；没有 agent 工具执行循环。未来可在同一读取底座增加邮件问答和线程分析。
- 先按 60 秒轮询，避免在首版引入不同 IMAP IDLE 兼容问题。真实可见延迟包括轮询、模型和通道等待；不承诺秒级。
- 从邮件头解析 From/To/Cc，实际收件邮箱以配置中通过认证的账号为准。密送和转发不猜测原始信封收件人。
- 同报文跨账号不合并主动通知，以保留用户要求的接收来源。模型无法覆盖或修改来源元数据。
- 测试替代所有外部服务；真实设备、账号和供应商联调由用户配合完成。

边界：

- 单用户、本机控制台。无公网访问、多用户、OAuth、附件正文分析、自动发信、自动删除、自动规则学习。
- 云摘要按邮箱主动启用，敏感邮件只提醒。只做常见隐私匹配，不能声称完整脱敏。
- 首次基线跳过历史邮件；UIDVALIDITY 变化人工确认再重建。历史归档与自动重扫暂不交付。
- 普通邮件模型故障时只生成降级提醒，当前版本不自动事后补全失败摘要。
- 手机实际送达、通知展示和完整真实摘要质量不能由 mock 证明。

完成标准：源码可直接启动；离线测试通过；演示链路可重复；真实测试清单具体可执行；清楚报告真实联调结果未被验证。

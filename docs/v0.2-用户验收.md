# v0.2 用户验收：邮件工作台

你已反馈 v0.1 的 README 第 6 节测试全部完成、效果不错。本轮不用重配邮箱；旧数据保留，也不会自动重发历史通知。

1. 停止旧程序，用原来的启动脚本重新启动，打开 `http://127.0.0.1:8788`。确认工作台能显示已有邮件。
2. 搜索一封已知邮件的主题/发件人/摘要关键词，再选择某个邮箱；确认来源正确。“重置”恢复全部邮件。每页最多 20 封。
3. 看“需要行动”，确认模型识别的待办集中显示；它还不支持标记完成。“需要检查”包括摘要降级和推送异常；“含附件”仅筛选附件名称，不做解析。
4. 打开详情，核对发件人、To/Cc、实际收件账号；点击“查看清洗后正文”展开纯文本。
5. 打开“偏好设置”，只改某个邮箱的显示名称，点击“保存设置并停止本次运行”。等终端显示“已停止”，重新启动；确认设置保留。旧邮件保留旧标签，新收到的邮件使用新标签。
6. 将摘要风格设为“简短”或“详细”，保存并重启，再发送一封普通测试邮件，比较新摘要。旧摘要不重算；模型可能没有完全遵循长度偏好，请反馈遗漏的重要事实。
7. 可选隐私验证：关闭一个邮箱的云摘要，保存并重启，给它发普通测试邮件，应得到未授权摘要的提醒；之后恢复授权，同样需要重启。附件始终不解析。

如果保存失败，配置应保持原样；刷新设置页后再试。只运行 `web` 或演示模式时不能保存，这是预期行为。

反馈界面问题可提供页面名称和脱敏截图；反馈模型问题可提供合成测试内容及摘要。不要发送凭据或个人敏感邮件。

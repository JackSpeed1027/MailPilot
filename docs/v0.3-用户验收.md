# v0.3 页面配置与外文阅读验收

升级先关闭旧运行窗口，保留 config.json、data 和 .venv；双击项目根目录的 **Start-MailPilot.cmd**，自动打开本机设置页面。无需在控制台输入授权码或 API Key。

## 1. 页面填写

1. 检查原有邮箱显示名称；已有地址不变。新用户在“添加一个邮箱”选择 QQ、163、Gmail，填写地址、备注和授权码。
2. 需要总结、翻译的邮箱勾选云处理授权。填写模型 HTTPS 基础地址、模型名称、API Key，开启模型和全文翻译。建议先选择详细摘要。
3. 按页面官方链接获取 WxPusher AppToken、本人 UID，分别填写并启用。
4. 默认密钥仅本次运行；想下次免填，勾选 Windows 凭据保存。保存后密码框应清空，配置文件不含密钥。
5. 等待页面显示收件已启动；刷新首页检查各邮箱连接正常。如果提示缺少凭据，回设置页补充后再保存。
6. 首次成功连接建立基线，随后才发新邮件；历史邮件不补收。开启了凭据保存后，关闭、重启一次检查能否自动收件。若端口占用，先检查旧窗口是否仍运行。

## 2. 英文普通邮件

发新邮件：主题 `Verification report and meeting`，正文：

> Please review the verification report before Friday's meeting at 10:00. The approved budget is CNY 12,800. This is a one-time payment for the project. Please reply to confirm attendance.

期望：普通邮件，不显示验证/登录隐藏提示；详情分别有中文摘要、完整中文译文、英文原文。会议时间、预算、付款性质和回复要求不应遗漏或被编造。核对通知中的发件地址、To / Cc、实际收件邮箱。

不能用这封合成例子断定原先英文样本的具体误判词；原英文内容未提供，如仍有问题，可给出脱敏主题/正文及结果，不要给密钥。

## 3. 日文邮件

重新发送之前的日语测试邮件。原文明确表示“确认邮件收发系统正常；没有业务内容；可以忽略”，所以中文摘要说测试邮件本身是合理的。

期望：另有完整中文译文，包含问候、测试目的、无业务内容、可忽略、结束问候、署名和日期；原文可直接看到。再发一封**真实含业务信息的合成日文**：

> 件名：テストメール：会議のご案内
>
> 10月16日午前10時に会議を開催します。予算は12,800元です。10月14日までに出席の可否をご返信ください。

期望：不能因主题有“测试”就只总结成测试邮件；摘要应覆盖会议、预算、回复期限，译文完整。

## 4. 失败和隐私边界

- 普通验证码邮件（使用无效合成验证码即可）仍应隐藏正文，不交给模型。
- 关闭某邮箱云处理授权后，新邮件本机保留原文，摘要显示未授权。不能因后续开启就自动补传旧邮件。
- 将每日调用尝试上限调低，达到后应明确提示。分段翻译耗尽时显示未完成，不能写“全文完成”。测试后恢复上限。
- 关闭全文翻译后，新外文邮件有摘要和原文，详情提示未开启译文。
- 超长通知会明确标为节选；完整译文在本机详情里。手机无法直接访问电脑 127.0.0.1。
- 更换模型 API 服务地址，Key 留空时不能沿用另一个地址的旧 Key。确认新服务的地址后再填新 Key。

## 已知边界

本版自动测试使用合成数据/模拟模型，没有使用你的实际密钥调用模型，也没有替你发送真实通知。测试通过证明流程和约束，不证明所有译文语义正确；请重点验收事实、金额、时间与完整性。

旧版敏感误判邮件没有存正文，升级不能恢复已丢弃正文；请重新发新测试邮件。已有普通邮件的旧摘要也不会自动翻译或重算。尚无原邮件定向重新读取按钮、附件/图片解析、Agent 检索问答、Android 应用或独立桌面安装包。

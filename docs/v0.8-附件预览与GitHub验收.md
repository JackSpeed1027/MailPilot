# v0.8：本机文字附件预览与 GitHub 版本管理

日期：2026-10-14。项目仓库：[JackSpeed1027/MailPilot](https://github.com/JackSpeed1027/MailPilot)。

## 如何开启附件预览

1. 关闭旧运行窗口，重新双击 `Start-MailPilot.cmd`。
2. 设置 → 我的邮箱 → 对应邮箱“管理”。
3. 勾选“在本机预览新邮件的 TXT / CSV / Markdown 附件（不上传模型）”，保存并应用。
4. 发一封附带文字文件的新测试邮件，阅读页下方“附件”会显示文件名和状态。点文件名展开文字。

默认关闭，每个邮箱独立选择。普通邮件的云处理授权与本机附件预览是两个不同选项，开启预览也不会把附件文字交给摘要、回复或跨邮件助手。关闭后不再提取新附件；之前已保存在本机数据库的预览仍保留。旧邮件没有原附件，不自动回溯提取；开启后只作用于新收到的邮件。

## 本版支持和边界

支持 TXT、CSV、MD/Markdown 的**文字预览**。CSV不会执行公式，Markdown不会执行HTML或远程内容，也没有渲染成富文本。识别 UTF-8/BOM、UTF-16 BOM、声明的文字编码以及 GB18030。文件名只用于显示，不创建文件路径；原文件和原始MIME不落盘，提取结果保存在现有 SQLite 邮件记录中。

每个附件最多256,000字节、12,000字符；每封最多预览前10个附件，合计30,000字符。整封邮件仍受默认2MB收信上限限制，超过整封限制时只取邮件头，无法预览附件。超长文字明确显示“部分文字”；超限、二进制、无法识别编码或不支持类型给出状态，不伪装成解析成功。验证/登录类附件不保存文字预览，受保护邮件不进入附件解析。

PDF、图片、Office文件本版暂不解析。PDF提取需要独立的资源控制，不能因为安装了库就认为可以安全处理所有文件；扫描PDF还需要OCR。[pypdf 官方文字提取说明](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)。后续按类型独立授权，图像、PDF与云模型理解分阶段接入。

## 请验收

1. 默认关闭时发 TXT，确认只显示未开启预览，不出现文件内容。
2. 开启后发一个中文TXT、CSV或Markdown，确认可展开阅读；附件内容不应混进正文摘要。
3. 上传给测试邮箱的文件可以包含文字 `<script>` 或CSV公式，应作为普通文字显示，不执行。
4. 发超过12,000字符的TXT，确认标注部分文字；256KB以上应提示超限。
5. 发图片/PDF，确认明确提示暂不支持，而不是空白或假成功。
6. 关闭预览再收一封新文件，确认停止提取；历史预览继续作为本机记录保留。

## GitHub怎样记录每一版

从本版起不新增 ZIP 源码归档。已有 v0.1–v0.6 快照与当前 v0.7 源码导入 Git，建立 `v0.1.0` 至 `v0.7.0` 标签；本版为 `v0.8.0`。这是2026-10-14进行的历史迁移，不伪造旧日期的 GitHub提交。早期文档中的疑似令牌示例会脱敏，个人配置、密钥、真实邮件、虚拟环境和 ZIP 不入库。

每版仍更新“版本演进与技术复盘”和“开发验证记录”，Git提交保存代码变化，标签定位该版，GitHub Compare查看前后差异。历史 ZIP 原件暂留在原电脑，本版不会再创建新的归档。以后在这个项目目录继续使用 Git，不另外生成永久代码副本。

新增 GitHub Actions离线测试：Windows/Ubuntu × Python3.11/3.13，使用官方Actions固定提交，不使用邮箱或模型密钥。远程CI结果与本机测试分开记录；未完成的远程检查不能写成已通过。

## 本版验证

144项离线回归（原135 + 新9），涵盖默认不解码、编码与MIME、文件/字符/数量上限、验证内容保护、路径不落盘、HTML逃逸、本机设置开启/关闭，以及模型上下文不包含附件文字。开发使用合成文件，不调用真实模型、不发送真实邮件。Git上传前检查整个历史和最终文件清单，不只依赖 `.gitignore`。

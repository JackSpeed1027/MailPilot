## v0.1：先做完整业务链路

### 为什么这样做

目标先验证“读到邮件 → 总结 → 手机上看到通知”，选择 Python 标准库和 SQLite，避免基础版本先部署数据库服务器、队列和前端构建环境。它是有模型参与的受控处理流水线；没有自动回复、任意工具执行或自主规划，简历应准确描述为邮件摘要助理，而不是声称已实现完全自主 Agent。

### 完成与解决的问题

| 问题 | 方案 | 为什么有用 |
| --- | --- | --- |
| To 字段不能说明实际在哪个邮箱收到 | 同时记录邮件头 To/Cc 和采集账号 | 转发、别名、密送仍能说明真实来源 |
| 每次启动把历史邮件全部推送 | 首次连接建立 UID 基线，只处理之后的邮件 | 避免历史洪水和额外模型费用 |
| 写库失败却推进了游标 | 邮件入库和游标推进在同一事务中 | 避免重启后永远跳过未保存邮件 |
| 重试引起重复通知 | 精确重复抑制；明确失败有限重试；超时记 unknown | 承认网络请求结果可能不确定，不虚称严格 exactly-once |
| 一个邮箱故障拖住其他邮箱 | 每账号独立采集线程，摘要/发送分开 | 隔离网络故障；不声称 CPU 并行加速 |
| 邮件包含验证码、隐藏 HTML 或指令 | 清洗、规则保护、模型仅做结构化摘要 | 降低敏感信息外发和邮件提示注入风险，规则仍有漏判边界 |
| 模型出错后邮件静默消失 | 保存邮件并生成降级提醒 | 模型不是收件成功的前提 |
| 凭据泄漏到仓库/控制台 | 配置只存凭据名称，运行时隐藏输入 | 退出后重新输入；当时尚无系统凭据库 |
| Windows 中文显示/启动脚本乱码 | CLI 输出 UTF-8；PowerShell 5 脚本使用 UTF-8 BOM | 适配用户实际电脑环境 |
| 代码散落在旧目录 | 集中到指定 MailPilot 目录并清理已核实的重复副本 | 用户可直接找到项目与数据 |

### 测试和不足

初版 51 项离线测试覆盖解析、游标、敏感信息、去重、故障降级、推送状态、HTTP 页面、运行锁及模拟端到端流程。没有记录可公平复用的 v0.1 性能基线，所以**不能据此计算 v0.2 相比 v0.1 的速度提升**。

用户实测后反馈基础链路效果良好。长期断网恢复、手机锁屏接收稳定性、真实费用、摘要质量量化仍没有完整证据。安装包、OAuth、历史导入和文件理解当时没有完成。

## v0.1 文档修订：让非开发者可以配置

用户提出“不知道显示名称是什么，也不知道 WxPusher 官网和获取方法”。README 改为从准备材料到测试新邮件的顺序，逐项解释提示、默认值、隐藏输入、授权码与普通登录密码的区别，并链接官方服务入口。发现模型默认值与当时官方文档不同，明确要求手动填写已核实的示例值，没有擅自改动用户已跑通的模型配置。

经验：能运行的命令不等于能用的产品；初次配置需要例子、错误恢复和明确的成功条件，`accepted` 不能替代手机看到消息。

## v0.2：让数据可以日常浏览和设置

### 完成内容与前后区别

| 方面 | v0.1 | v0.2 |
| --- | --- | --- |
| 浏览范围 | 首页固定最近 50 封 | 数据库全量搜索，每页 20 封，支持分页 |
| 找邮件 | 翻最近列表 | 搜索主题、发件人、实际邮箱、摘要和待办，组合邮箱筛选 |
| 行动视图 | 各邮件中零散显示 | 集中“需要行动”；它代表模型识别的待办，尚无完成/提醒管理 |
| 异常视图 | 阅读任务状态 | “需要检查”聚合推送失败/不确定及摘要降级 |
| 邮件详情 | 摘要与正文平铺 | 摘要、重点、行动与来源分区；原文折叠查看 |
| 配置 | 手工 JSON 或终端向导 | 页面修改备注、正文云授权、摘要风格、间隔和调用上限 |
| 摘要风格 | 一种提示词 | brief / balanced / detailed，默认 balanced；效果待真实模型体验 |
| 授权撤销 | 待处理消息保留采集时授权 | 处理时同时检查采集授权和当前账号授权；新开启不补传未授权历史 |
| 性能证据 | 没有可比基线 | 固定合成数据与可运行脚本，保存环境及 P50/P95 |

### 关键实现与取舍

- `store.browse` 使用参数化 SQL、字面量通配符转义与分页；增加 `(account,id DESC)` 索引。搜索当前使用 JSON 字段 + LIKE，不是全文索引，也不能宣称百万邮件仍是固定耗时。
- SQLite 建表和新增索引是兼容旧数据库的操作，不重置游标、清空邮件或重发旧通知。老配置没有 `summary_style` 时按 balanced 加默认值。
- 设置只允许修改明确列出的字段，不接收任意 JSON；校验临时文件后原子替换，并通过版本摘要防止陈旧表单覆盖新配置。保留未知扩展字段和现有密钥引用。
- 页面只接受本机 Host；写操作检查 Origin 与随机 CSRF token。页面不渲染邮件 HTML、不加载远程资源，不暴露凭据值。
- 保存后要求运行器停止并重启，避免旧内存配置仍持续生效。当前批次检查停止信号，不再启动下一封摘要；已发出的请求无法撤回。这比直接动态更换全部线程参数更容易保持一致。
- `web` 仅浏览时禁止保存，避免独立浏览进程修改另一个运行器却不能让它停下。
- 显示名称改动影响后续采集；旧邮件保留采集时标签作为历史快照。旧摘要不重算，既不多收费，也不重发旧推送。

### 本轮测试中遇到的问题

最初测试在工具沙箱中遭遇临时目录权限和本机套接字访问限制，表现为 SQLite 无法打开测试数据库、HTTP 访问 WinError 10013。先将临时文件放入允许写的目录，再在获批的正常执行环境完成本机 HTTP 验证；没有修改业务代码绕过邮箱权限或 TLS 校验。

这类结果属于测试环境问题；不能把失败隐藏掉，也不能把“改测试目录后通过”写成业务性能优化。

### 验证结果

- Windows 项目虚拟环境：**66 项离线回归测试通过**，初次完整通过用时 9.422 秒。测试总时间不是应用处理邮件的耗时。
- 写回正式项目目录后复测同样 66 项通过，用时 9.147 秒；确认个人配置未被升级覆盖，文档链接与源码快照内容检查通过。
- 新增 15 项用例涵盖跨越旧 50 封限制、组合筛选、字面 `%/_` 搜索、异常视图、HTML 转义、授权撤销/后续授权、停止批次、真实提示词变化、原子保存、无效表单、陈旧表单、HTTP 保存及 Origin/CSRF 拦截。
- 实际合成页面在浏览器检查：桌面布局、窄屏布局、按 QQ 筛选为 1 封、详情的来源/摘要分区与原文折叠。合成演示不会证明真实模型的摘要质量。
- 当前附件仍只有名称，没有解析器、OCR、文件下载按钮或云附件上传功能。

真实设置体验和三种摘要风格按 [v0.2 用户验收](v0.2-用户验收.md) 继续确认，不能沿用 v0.1 的用户测试结论替代新增功能验收。

## v0.2 性能基线：以后优化的对照点

数据源：[原始测量 JSON](performance-v0.2.json)。环境：Windows 11、Python 3.13.16、SQLite 3.50.4、16 个逻辑 CPU。单进程、合成邮件、每页 20 条，每项预热 3 次后测 30 次；不计数据准备时间。

下表单位为毫秒，`P50 / P95` 表示一半样本与约 95% 样本所在的耗时位置：

| 测量内容 | 1,000 封 | 10,000 封 |
| --- | --- | --- |
| 全部邮件第一页（含计数） | 4.781 / 5.356 | 5.966 / 7.045 |
| 按账号筛选第一页 | 4.696 / 5.372 | 5.337 / 6.515 |
| 待办筛选第一页 | 7.738 / 8.461 | 29.553 / 32.228 |
| 关键词搜索第一页 | 9.627 / 10.508 | 48.867 / 53.656 |
| 首页生成 HTML（含状态与邮箱选项） | 14.674 / 16.392 | 20.234 / 22.313 |

**这不是邮件收取到手机的总延迟，也不是浏览器页面绘制时间，更不是 v0.1 → v0.2 的加速比。** 不含网络、真实模型和 WxPusher；数据都已处理，关键词样例在合成摘要中匹配，只有一个并发客户端。真实负载、磁盘缓存、杀毒和系统活动会影响结果。

观察：1 万封下 JSON 条件过滤/关键词扫描比首页普通分页贵，可以作为以后索引/全文检索实验的起点，尚不构成引入 Redis 的证据。

在项目目录复测，输出使用新文件，保留这一版原始基线：

```powershell
.\.venv\Scripts\python.exe -B .\tools\perf_baseline.py --output .\docs\performance-local.json
```

脚本只建独立临时合成数据库并自动清理，不读取 `config.json`、个人 `data` 或密钥，不发送网络请求。后续版本修改测量方法或数据时，必须记录变化，不能直接与本表计算加速比。

# v0.3：页面配置与多语言阅读（2026-10-12）

## 问题定位

英文“验证/登录类邮件”提示来自模型调用前的本机敏感规则，旧规则把 `verification`、`one-time` 等孤立词当作敏感依据，可能误伤验证报告、一次性付款等普通内容。由于没有拿到原始英文样本，不能认定那封邮件的具体触发词，更不能将原因一概归咎于 LLM。

用户提供的日文正文明确是系统收发测试、无业务内容、可以忽略。摘要称测试邮件合理；缺陷是旧流程只生成摘要，没有独立全文译文，以及前段输入长度限制没有向用户充分说明。

本版把敏感规则收紧为验证码语义与附近实际代码、明确认证请求、带链接的认证动作；保留中英日验证码保护，检查 HTML 的隐藏文本/替代正文。规则仍可能误判或漏判，不能保证识别所有隐私信息。

## 具体实现与学习点

- 新增 `ui` 命令与双击启动入口。用户在页面添加邮箱、填写密钥、模型 API、WxPusher、摘要和翻译偏好。配置校验后原子写入；版本摘要校验防止旧窗口覆盖。
- 使用 Windows 原生 Credential API，核心仍零第三方依赖。默认密钥只驻留本次进程，选择记住后写入当前用户凭据库，HTML 与 JSON 不含密钥。凭据绑定项目、邮箱或模型地址，防止换服务地址泄漏旧 Key。保存过程中失败尽力回滚凭据变化，配置文件保持原子替换；操作系统拒绝回滚时不能承诺跨存储事务原子性。
- 控制器等待旧任务退出再应用配置，不在未结束的任务上切换模型地址或密钥。缺少启用功能所需凭据时保存配置但不启动采集。启动状态与各邮箱实际健康结果分别展示。
- 摘要独立返回语言信息；外文正文分段译为中文，保留问候、业务内容、署名、日期。常见 URL、邮箱、长号码先变成随机占位符，译后本地恢复，并校验每个占位符恰好一次。这不是全面匿名化保证。
- 翻译只在模型明确 `finish_reason=stop`、结构与占位符通过校验时接受；长度截断、调用耗尽、格式错误显示失败/部分完成。占位符在切段前替换，避免私密字段横跨分段边界。
- 长外文邮件翻译各段并提取事实，成功后再合并全篇摘要；合并失败保留完整译文、明确标记摘要只覆盖前段。中文长邮件仍标出前段摘要范围。
- 摘要、分段翻译、合并共享已有每日尝试上限；已验证的 DeepSeek 当前模型按官方接口禁用默认思考模式，避免阅读任务输出预算被思考占用。其他服务不发送该专有参数。
- 详情按摘要、译文、原文、来源分区；短外文推送可含全文，长内容明确标为节选，保留本机完整内容。

## 数据兼容与尚未完成

保留现有 SQLite 结构、邮箱配置与 .venv；旧配置加载时补齐翻译默认值，不自动重写用户文件。缓存结果增加分析版本，避免将旧流程结果直接复用于新处理。旧敏感误判正文已在入库前丢弃，不能从旧数据库恢复；需要重新发送新测试邮件。旧记录不自动补翻译，也不重发已接受通知。

尚无定向重新读取旧邮件、GUI 合成接口测试按钮、附件/图片解析、工具调用 Agent、RAG 检索问答、Android 成品、桌面安装包。页面配置覆盖日常邮箱/API/推送需求；删除账号、自定义服务器、文件夹和数据目录仍需停止程序后编辑配置。

## 验证与成本变化

新增回归共 **92 项离线测试**（原 66 + 新增 26），包含英文普通语义、实际验证码、日文样例路由、完整译文独立于摘要、分段文本保留、截断不假称完整、共享调用上限、超限、隐私授权、HTML 转义、长推送节选、配置校验与 CSRF/Origin、Key 地址隔离、Windows 唯一合成凭据写读删除、任务退出后再重启和凭据失败回滚。Windows Credential 测试只操作自己创建的唯一合成条目。

新增跨段用例发现，占位符恰在边界且前缀未完整落在前段时会被切开，导致本地私密字段无法恢复；随后改为定位方括号并校验完整随机占位符，再避开切段。另增加正文伪造长占位符场景，避免未经验证的正文文本造成切段循环停滞。这些属于开发期间发现并修复的问题，不是宣称真实模型已经通过质量验收。

浏览器实际保存了隔离环境的合成邮箱配置：密码留空，页面提示缺少凭据，不启动联网任务；检查摘要/中文译文/日文原文/来源布局。预览译文是固定合成结果，不能当成真实 LLM 的质量成绩。真实模型、真实推送和授权保存体验由 [v0.3 用户验收](v0.3-用户验收.md) 补充。

调用量变化：短中文一般 1 次；短外文通常 2 次（摘要 + 翻译）；长外文约为 1 次初摘要 + N 段翻译 + 1 次合并，失败/超限时不同。N 按分段长度和段落边界决定，默认每段最多约 2000 字符（占位符处理可能影响分段）。这是实现推导，不是实付费用或速度实测。原 v0.2 查询性能 JSON 保留，没有宣称加速或 Redis 优化效果。后续评估需同时记录译文完整性、关键事实和成本。

# v0.4：阅读清理、手动回复与受限工具 Agent（2026-10-12）

## 触发问题与功能变化

用户确认多语言问题解决，随后指出 `&nbsp;` 暴露到阅读界面，希望应用能直接回复邮件，并学习 Agent 的工具调用与个性化流程。

HTML 解析器只会处理 HTML 正文里的实体；纯文本中仍有实体、双重编码或旧数据库内容时，会被再次转义成可见字样。本版增加受限层数的实体解码与空白规范化，同时在解析、模型输入、显示与推送路径处理。显示层仍 HTML 转义，因此编码后的标签不会变成可执行页面。旧记录无需重写，旧已发送通知无法改变；手工输入的草稿按原样保留，模型草稿额外清理实体。

## 回复与数据设计

使用标准库 SMTP_SSL 与验证证书的默认 TLS 上下文，不引入自建发信服务器。对应邮箱 `smtp_enabled` 默认关闭，用户开启 SMTP 后从实际收件账号发送；保存 Reply-To / References，回复优先 Reply-To，无唯一合法地址则拒绝，保留线程头。旧记录无 Reply-To 时明确提醒按 From 回复。

新增 SQLite `replies` 表保存草稿与发信状态、`agent_runs` 表保存起草状态与结构化步骤，采用只增加表的前向兼容迁移。用户先保存预览，再点击确认；草稿 revision 防止预览过时，事务领取发送状态阻止同一草稿重复提交。SMTP 提交前失败与提交后未知分开，成功后 QUIT 失败不覆盖接受状态；未知不自动重发。安全启动时在能够取得既有数据目录锁的条件下恢复中断发送为 unknown，避免干扰仍在运行的另一进程。

POST 成功后重定向到稳定的草稿 GET 地址，避免刷新再次提交、空白或404。表单错误保留所写内容；正文/地址转义、Origin 与 CSRF 检查、字段白名单和上限继续适用。

服务端接受不等于对方已读或必然进收件箱；原邮箱“已发送”文件夹暂不做 IMAP APPEND。没有回复全部、附件回复、自动发送或严格 exactly-once 保证。

## 第一个真实的受限 Agent 流程

这是单任务邮件回复 Agent，不是整个系统已自主化：

1. 用户点击智能起草，程序绑定当前邮件与账号，验证 SMTP 能力、收件时与当前云授权、正文完整长度、模型开关及 Key。
2. 模型自行选择 `get_email_context`、`get_reply_preferences` 两个只读工具。工具无可修改邮件ID的参数，不能遍历其他邮箱；逐一验证名称、参数、调用ID、重复与数量。未知/重复工具立即停止，不执行。
3. 程序提供清洗、常见隐私脱敏后的当前主题/正文，以及用户明确设置的语气、长度、语言、偏好说明。署名不上传，后续本机添加。没有自动扫描历史邮件学习习惯。
4. 两个工具都调用成功后，模型输出 subject/body JSON；拒绝额外收件地址、截断、结构不符、超长或换行主题。最多3轮请求，共享原有每日预算，通常2轮。
5. 生成后只保存草稿，用户修改、核对并发送。模型没有 SMTP、脚本、网络浏览或发信工具。

`agent_runs.trace` 只记录请求轮次/耗时、工具名及校验步骤，不保存模型内部思维、不记录工具正文或密钥。页面可展开实际步骤。格式与权限验证不是语义正确性证明，模型仍可能编造，重要事实和承诺必须核对。

选择直接实现兼容 Chat Completions 的 tools 协议，维持零第三方依赖；当前只有两个工具和3轮，不需先加编排框架。未来工具/状态复杂再评估框架。RAG 留给明确的历史邮件问答：先全文检索基线，再评估跨语言语义召回、引用和成本，不为了简历添加无实际用途的向量库。

## 模型调用可观察性

原 MIME / HTML / 实体解析在本机完成，摘要、翻译、智能起草才用模型。本次只读排查确认当时本地已记录当天10次接口响应、6份 model 摘要，不读取正文、邮箱地址或密钥；这不能证明服务商账单统计原因。今后详情标明模型/本机结果，设置显示每日尝试与响应计数，后台无记录需对照 Key 账号/项目、接口地址与日期筛选。打开旧结果不触发新请求。

新增26个独立用例，连同原92项，当前共118项离线回归。覆盖实体与双重编码、旧记录转义、编码验证码保护、Reply-To 与线程头、单收件人与头注入拒绝、SMTP开关、草稿版本、幂等领取、QUIT异常、提交前失败/提交后未知、启动恢复、工具选择、越权/错误参数/重复工具拒绝、脱敏与署名本机追加、预算共享、无云权限、输出截断、过长正文、HTTP确认与跨站拒绝。模型与 SMTP 都是模拟，不用真实 Key，不发送真实邮件。

## 数据库决策

目前继续 SQLite，文件默认 `data/mailpilot.sqlite3`；WAL、短事务适合单用户本机邮件与草稿。Store 是已有数据访问边界，当前查询依赖 SQLite JSON/语法，不虚假声称 MySQL 可直接替换。

若加入统一登录、团队共享、多设备同步：客户端保留 SQLite，后端以 HTTPS 服务集中授权和同步，MySQL 位于服务器/私有网络，由后端连接。开发可放自己电脑，正式服务可租服务器或使用持续在线的自有硬件；用户下载客户端不应被要求安装 MySQL。迁移需明确接口、驱动、SQL方言、索引、事务、数据导入和回滚。当前不提前部署 MySQL 或 Redis。

# 用户测试清单

开发者可完成代码与离线模拟测试；下列项目依赖你的真实账号、网络和手机。不要把授权码、appToken、API Key 发到聊天中。

1. **本机演示**：在项目目录运行 python -m mailpilot demo，再运行 python -m mailpilot web --demo。打开 http://127.0.0.1:8788，确认 QQ、163、Gmail 三条邮件分别显示实际收件账号，摘要和待办可读。Ctrl+C 停止。
2. **配置**：运行 python -m mailpilot setup。先只加一个真实邮箱。允许正文云摘要才选 y；指定模型服务商及 WxPusher 本人 UID。后续编辑 config.json 添加其他邮箱。
3. **只读登录**：运行 python -m mailpilot doctor --online --prompt-secrets。分别记录 QQ、163、Gmail 的成功或失败；失败时只回报命令输出和服务商类型，不发凭据。Gmail 如果账号不允许应用专用密码，报告需要 OAuth。
4. **模型**：运行 python -m mailpilot test-model --prompt-secrets。确认 mode 为 model、合成英文邮件被总结成中文，报价 12,800 元、周五 10:00 信息正确。这里发送的是合成内容。
5. **推送**：运行 python -m mailpilot test-push --prompt-secrets。确认程序结果 accepted，并在手机看到 MailPilot 测试通知。记录使用 WxPusher 哪个接收端、是否能看到通知摘要。accepted 不能代替手机确认。
6. **真实英文摘要**：运行 python -m mailpilot run --prompt-secrets。等控制台显示邮箱正常，再从另一邮箱发新邮件：“Please confirm Friday's meeting at 10:00. Revised quote: CNY 12,800.” 等待约 1～2 分钟。检查收到的摘要是否中文、金额时间正确、发件人邮箱正确、实际收件账号正确。
7. **来源**：同一封邮件同时发给你的 QQ、Gmail。应有两条通知，各自显示实际收件账号；原始 To 可能都列两人，这与实际收件账号是不同字段。另发一封密送邮件，实际收件账号仍明确显示。
8. **中文、HTML、附件**：发中文通知、一封 HTML 正文邮件和一封带小附件的邮件。确认主题不乱码、HTML 有可读摘要、附件仅列文件名、不总结附件内容。
9. **验证类邮件**：自行发合成“验证码 867530”，确认通知只有验证类提醒，正文数字不出现在控制台或模型摘要中。此项是启发式保护用例，不代表所有真实敏感格式均已覆盖。
10. **重启**：收到通知后停止并重新启动 run，确认已完成的邮件不再重推。默认 restart 仍需输入凭据，符合当前内存凭据设计。
11. **断网恢复**：运行时断网约两分钟，期间收到一封新邮件；恢复网络后确认能补拉并通知。第一版轮询重连，不承诺 15 秒内恢复。
12. **模型失败**：停止 run，将模型名称临时改成一个无效名称，重启后发合成普通邮件。确认收件和来源仍保留，通知说明自动摘要暂不可用。恢复模型配置后继续使用。
13. **真实账号日用**：先试用一天，记录有用摘要、错误待办、误屏蔽为敏感的普通邮件、重复或未收到通知。只提供脱敏样例和控制台状态；有问题继续修正并加入回归测试。
